# 数据备份目录

> 本目录由「公众号成长日志」应用的数据备份自动持久化维护，防止数据丢失。
> 数据口径与恢复方法详见仓库根目录 [DATA.md](../DATA.md)。
>
> ⚠️ 本目录会随站点部署并公开提供（`backups/latest-cloud.json` 是断云兜底数据）；仓库为公开仓库时，其中文章标题 / 阅读量 / 周报备注也可被直接下载。口令只保护 Cloudflare KV 实时数据，敏感数据请改用私有仓库或移除兜底文件。

## 文件说明

| 文件 | 含义 |
|------|------|
| `cloud_YYYY-MM-DD.json` | **云端历史备份**：旧版本直连云端拉取的整包（`_meta.source: "cloud"`），云端此刻有多少导多少 |
| `local_YYYY-MM-DD.json` | **本机快照**：导出时该设备内存中的数据（`_meta.version: "3.0"`；2026-10-26 这份为旧版 v2.0 导出） |
| `merged_YYYY-MM-DD.json` | **恢复合并快照**：云端不可达、需要把本地新数据合并进兜底时生成（保留原阅读量 / 墓碑），不等于云端直导 |
| `latest-cloud.json` | 最近一次云端全量备份（覆盖式更新，始终最新）；2026-10-26 为恢复合并快照 |
| `latest-local.json` | 最近一次本机快照（覆盖式更新，始终最新） |
| `HISTORY.md` | 每次备份的索引（日期 / 计数） |

- 同一天多次导出会覆盖同名日期文件，旧版本仍保留在 git 历史中，可随时回溯。
- 想要最新全量数据：直接下载 `latest-cloud.json` 即可。
- 2026-10-26 的 `latest-cloud.json` 是**恢复合并快照**：旧云端项目当时不可达，由 `local_2026-10-26.json` 与 `cloud_2026-09-14.json` 合并生成，保留旧阅读量 / AI 标记 / 墓碑，并加入 2 篇新文章、2 条周报。后端迁移到 Cloudflare KV 后，应以 KV 实时数据为准。

## 安全性

- 备份文件**不含访问口令、不含任何密钥**（应用口令只以 SHA-256 哈希存于 Cloudflare KV，从不出现在数据中）。
- 每次入库前自动做结构校验 + 敏感字符串扫描，校验不过不会推送。

## 恢复方法

在网站「数据总览 → 数据管理 → 导入历史数据」选择任一备份 JSON 即可合并导入
（应用内置字段级清洗，相同记录自动去重；v3.12 起同时按当前墓碑与备份内墓碑过滤，已删除记录不会被旧备份复活），适合换设备 / 数据丢失时一键恢复。
